# Phase 2: 扩展 examples 与 jsx 页面覆盖

Phase 2 的重点是把 [app/pages/examples](../../app/pages/examples) 和 [app/pages/jsx](../../app/pages/jsx) 中真正会拖动 runtime 行为的页面，逐步拉进页面级回归矩阵。

## 目标

1. 让 examples 目录里高交互页面至少各有一条主流程测试。
2. 让 jsx 目录里体现编译输出与 runtime 行为边界的页面至少各有一条主流程测试。
3. 把“已有低层测试，但缺页面入口哨兵”的功能块补齐到可安全删除代码的程度。

## 建议优先级

1. examples：在现有 [helloWorld.actual.spec.tsx](../../packages/runtime/__tests__/helloWorld.actual.spec.tsx)、[todoApp.actual.spec.tsx](../../packages/runtime/__tests__/todoApp.actual.spec.tsx)、[treeView.page.spec.tsx](../../packages/runtime/__tests__/treeView.page.spec.tsx)、[modal.actual.spec.tsx](../../packages/runtime/__tests__/modal.actual.spec.tsx) 基础上，继续补 Slots、MarkdownEditor、FormBindings、SortFilterGrid、FetchingData。
2. jsx：在现有 [controlledInputs.actual.spec.tsx](../../packages/runtime/__tests__/controlledInputs.actual.spec.tsx) 基础上，优先补 DynamicComponent、SuspenseDemo、TemplateDemo、Refs、Children、VModelAndRModel。
3. 对已经有低层回归但缺页面入口的功能，页面测试只补最能代表主流程的一条，不重复堆同质断言。

## 工作内容

1. 为每个目标页面列出“最小可断言主流程”，例如输入、切换、添加/删除、异步加载、slot 输出、列表更新。
2. 复用 [page-test-utils.ts](../../packages/runtime/__tests__/page-test-utils.ts)；必要时只做小幅增量扩展，不另起一套 helper。
3. 对 examples / jsx 页面沿用“直接挂页面组件”为主；只有页面本身必须依赖路由参数时，才引入真实 router context。
4. 每补 2 到 4 个页面测试，就跑一次对应窄范围 vitest，防止一次性堆太多不稳定用例。

## 风险

- examples 与 jsx 页面里有一部分会同时依赖 Slot、Template、Suspense、KeepAlive、动态组件和指令编译输出，断言过宽容易变脆。
- 若在扩测过程中顺手去修低层实现，容易把“建护栏”和“继续删代码”重新耦合在一起。

## 完成标准

1. examples 目录的高交互页面都已具备页面级主流程测试。
2. jsx 目录里和 runtime 边界关系最强的页面已进入测试矩阵。
3. 新增测试都能映射到具体后续删除切片，而不是只形成零散 smoke test。
