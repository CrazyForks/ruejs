# Phase 4: 构建、测试、文档与发布清场

前三个阶段解决的是“代码是否已经完成迁移”，最后一个阶段解决的是“仓库口径是否已经跟着完成迁移”。只要 build/docs/test/release 还在把 compat 或 virtual DOM 当作活动系统，Plan 12 就不能算真正收尾。

## 当前信号

- [packages/global.d.ts](../../packages/global.d.ts) 里仍声明 `__COMPAT__`。
- build/dev 配置仍保留 compat 相关分支，代表性文件包括 [rollup.config.js](../../rollup.config.js)、[vite.config.ts](../../vite.config.ts)、[scripts/dev.js](../../scripts/dev.js)。
- [scripts/check-compat-cleanup.js](../../scripts/check-compat-cleanup.js) 仍把 compat 文档、migration 文档和旧术语清理视为持续中的检查任务。
- [docs/about/compat-policy.md](../about/compat-policy.md)、[docs/getting-started.md](../getting-started.md) 以及 render-function / rendering-mechanism 一组文档里，仍把 compat / VNode 当成活动叙事的一部分。
- [docs/api/render-function.md](../api/render-function.md)、[docs/api/composition-api-helpers.md](../api/composition-api-helpers.md)、[docs/api/component-instance.md](../api/component-instance.md)、[docs/guide/scaling-up/testing.md](../guide/scaling-up/testing.md) 仍把 `RenderOutput` / `RueMountHandle` / `h` 当成可公开使用的活动 API 叙述。

## 目标

1. 删除 `__COMPAT__` 与双模 build/dev 假设。
2. 删除或改写 compat-policy、migration、release 里已过时的 compat/virtual DOM 叙述。
3. 清理不再需要的 compat tests、legacy terminology guards 与 release note 例外规则。
4. 清理 API docs、测试文档与示例里仍把 `RenderOutput` / `RueMountHandle` / `h` 当默认 contract 的内容。
5. 为最终发布提供新的 migration 文档和 changelog 口径。

## 工作内容

1. build/config 清场。
   删除 `__COMPAT__`、compat build define、双模开发入口和已经没有意义的输出差异。
2. test/check 清场。
   把 [scripts/check-compat-cleanup.js](../../scripts/check-compat-cleanup.js) 改成新的永久 guard：禁止 compat 术语、禁止旧 VNode contract 回流，而不是继续为历史迁移文档保留例外。
3. docs 清场。
   处理 compat-policy、getting-started、render-function、rendering-mechanism、release notes，把旧叙事改成历史说明或迁移完成说明，并同步清理 API docs、测试文档和示例里对 `RenderOutput` / `RueMountHandle` / `h` 的默认公开表述。
4. 发布口径清场。
   形成一份明确的 major release migration note，说明 Plan 12 删掉了哪些 contract、保留了哪些最终 contract。

## 工作量判断

- 规模：Medium
- 预估：约 3 到 5 个工作日
- 原因：代码复杂度不高，但分散且容易漏；真正的难点是确保没有历史术语、脚本例外和文档口径残留。

## 依赖与风险

- 必须在前三阶段完成后再做，否则文档和 guard 会因为 contract 未定而反复改写。
- 这里最常见的失败模式不是代码错误，而是旧术语、旧路径、旧发布说明残留在 docs 或 scripts 里。

## 完成标准

1. `__COMPAT__` 与 compat build/dev 分支已从仓库移除。
2. compat-policy 与虚拟 DOM 相关历史叙述已经归档或改写，不再作为活动系统说明。
3. cleanup scripts 与 tests 已转成新的永久 guard，防止旧 contract 回流。
4. API docs、测试文档与示例里不再把 `RenderOutput` / `RueMountHandle` / `h` 当默认活动 contract。
5. 仓库具备一次对外发布 Plan 12 变更的完整口径。
