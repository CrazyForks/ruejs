# Phase 1: 建立页面级测试骨架与首批哨兵

这一阶段的目标不是追求覆盖面，而是先证明页面级 runtime 回归测试可以稳定落在 [packages/runtime/**tests**](../../packages/runtime/__tests__)，并且能卡住真实页面主流程。

当前状态：该阶段已经完成首批落地。

## 当前信号

- 已新增共享工具文件 [page-test-utils.ts](../../packages/runtime/__tests__/page-test-utils.ts)，统一提供 `flush`、`waitForContent`、history stub、DOM container 挂载等页面测试基础能力。
- 已新增四个首批页面测试：
  - [modal.actual.spec.tsx](../../packages/runtime/__tests__/modal.actual.spec.tsx)
  - [controlledInputs.actual.spec.tsx](../../packages/runtime/__tests__/controlledInputs.actual.spec.tsx)
  - [tabs.actual.spec.tsx](../../packages/runtime/__tests__/tabs.actual.spec.tsx)
  - [guideDocDetail.actual.spec.tsx](../../packages/runtime/__tests__/guideDocDetail.actual.spec.tsx)
- 这四个测试分别覆盖了 examples、jsx、design、site 四个目录的高价值主流程，且窄范围命令已经通过：
  - `CI=1 pnpm vitest run packages/runtime/__tests__/modal.actual.spec.tsx packages/runtime/__tests__/controlledInputs.actual.spec.tsx packages/runtime/__tests__/tabs.actual.spec.tsx packages/runtime/__tests__/guideDocDetail.actual.spec.tsx --reporter=basic`

## 目标

1. 固定页面测试落点：所有新页面回归统一放在 [packages/runtime/**tests**](../../packages/runtime/__tests__)。
2. 固定测试形态：优先“真实页面组件直接挂载 + 最小外围 mock”，避免一上来就走大而脆的 RouterView 全链路。
3. 固定首批目录样例：让 design/examples/jsx/site 四个目录各自都有一条可复用参考测试。
4. 固定验证节奏：每补完一批页面测试，必须先跑对应窄范围 vitest，再继续扩测或删代码。

## 重点文件

- [packages/runtime/**tests**/page-test-utils.ts](../../packages/runtime/__tests__/page-test-utils.ts)

- [packages/runtime/**tests**/guideDocDetail.actual.spec.tsx](../../packages/runtime/__tests__/guideDocDetail.actual.spec.tsx)

## 工作内容

1. 抽取共享的异步等待和挂载 helper，减少后续页面测试重复样板。
2. 选四个最能覆盖主流程的页面作为样例，而不是先去补纯静态文案页。
3. 对 design/examples/jsx 页面使用最小 wrapper mock，把测试焦点放在 runtime 行为而不是外围站点布局。
4. 对 site 文档详情页保留真实 route + fetch + markdown 注入路径，确保文档主流程被覆盖。

## 完成标准

1. 四个目录各至少有一条页面级 runtime 测试。
2. 共享 helper 已可被后续页面测试复用。
3. 首批页面测试在本地窄范围 vitest 下稳定通过。
4. 后续 Phase 2/3 可以直接基于这套骨架继续扩测，而不需要重新设计测试入口。
