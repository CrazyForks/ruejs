# Phase 2: 删除 JS runtime 的 VDOM / mount-handle 公开契约

彻底删除 virtual DOM 的真正大头不在 Rust，而在 JS runtime 公开面。当前 [packages/runtime/src/rue.ts](../../packages/runtime/src/rue.ts) 和 [packages/runtime/src/vapor-runtime.ts](../../packages/runtime/src/vapor-runtime.ts) 仍同时承接了 `RueMountHandle`、`RenderOutput`、compat anchor owner、`createElement/h/jsx-runtime` 等过渡契约。

当前进展：默认 runtime 已经不再调用 runtime-vapor 的 Wasm `createElement` builder；[packages/runtime/src/rue.ts](../../packages/runtime/src/rue.ts) 里的 `createComponent` 与 `vapor` 已改为 portable object 输出，`RenderOutput` 别名也已删除。剩余工作主要集中在 `RueMountHandle`、compat owner/pending anchor 跟踪逻辑，以及默认 package/jsx exports 的继续收缩。

## 当前信号

- [packages/runtime/src/rue.ts](../../packages/runtime/src/rue.ts) 里仍声明：
  1. `RueMountHandle`
  2. `RenderableInput = Renderable | RueMountHandle | ...`
  3. `RenderableOutput = Renderable | RueMountHandle | ...`
- [packages/runtime/src/rue.ts](../../packages/runtime/src/rue.ts) 与 [packages/runtime/src/vapor-runtime.ts](../../packages/runtime/src/vapor-runtime.ts) 里仍保留 `compatMountHandleOwner`、`pendingCompatAnchorRenders`、`RUE_FORCE_REMOUNT_ANCHOR_KEY`、`RUE_COMPONENT_CHILDREN_KEY` 这组 compat-anchor/mount-handle 跟踪逻辑。
- [packages/runtime/src/rue.ts](../../packages/runtime/src/rue.ts) 里的 `createElement/h` 已不再调用底层 Wasm `createElement`；函数组件走 portable component object，字符串标签会明确抛错，说明默认 runtime 已经进入“移除 VDOM factory 语义”的 breaking-change 阶段，但 package exports 与 JSX runtime 口径还没同步收完。
- [packages/runtime/src/index.ts](../../packages/runtime/src/index.ts) 与 [packages/rue/src/index.ts](../../packages/rue/src/index.ts) 仍默认导出 `createElement`、`RenderOutput`、`renderAnchor`、`renderStatic`、`h`、`Fragment` 这套历史使用面。
- [packages/jsx-runtime/src/index.ts](../../packages/jsx-runtime/src/index.ts)、[packages/jsx-dev-runtime/src/index.ts](../../packages/jsx-dev-runtime/src/index.ts) 仍通过 `h` 生成 `RenderableOutput`，而 [packages/rue/jsx.d.ts](../../packages/rue/jsx.d.ts) 仍把 `JSX.Element` 绑定到 `RenderableOutput`。
- [packages/runtime-vapor/src/hook/reactive.rs](../../packages/runtime-vapor/src/hook/reactive.rs) 里的 `shallow_equal_prop` 仍把 `__rue_mount_id` / `__rue_host_node` 当成 renderable identity 的一部分，说明 public contract 变化后还要同步改 comparator。

## 目标

1. 删除 public type surface 中的 `RueMountHandle` 与 `RenderOutput`。
2. 让 `render` / `renderBetween` / `renderAnchor` / `renderStatic` 只处理新的 renderable/block 契约，不再分 mount-handle / compat owner 分支。
3. 删除默认公开面里的 `h` / `createElement` / `Fragment` / JSX VDOM factory 语义，或将其移动到明确的历史迁移包之外。
4. 让 [packages/runtime/src/vapor-runtime.ts](../../packages/runtime/src/vapor-runtime.ts) 和默认 runtime 入口在 owner / cleanup / anchor 逻辑上收敛成同一个 vapor-only 口径。
5. 让 renderable identity / shallow comparator 与新的 public contract 对齐，不再依赖旧 mount-handle / host-node 兼容语义做默认比较。

## 工作内容

1. 缩 public types。
   从 [packages/runtime/src/rue.ts](../../packages/runtime/src/rue.ts) 删除 `RueMountHandle`、`RenderOutput` 与把 mount-handle 并入 `RenderableInput/Output` 的定义，把对外类型改成真正的 renderable-only / block-only 契约。
2. 先冻结 render entry 的 owner/cleanup 契约。
   先明确 [packages/runtime/src/rue.ts](../../packages/runtime/src/rue.ts) 与 [packages/runtime/src/vapor-runtime.ts](../../packages/runtime/src/vapor-runtime.ts) 中 `render` / `renderBetween` / `renderAnchor` / `renderStatic` 的最终 owner model，再删除 `compatMountHandleOwner`、pending remount、mount-handle owner sync 分支；否则 Teleport、Transition、RouterView、custom-elements 的迁移目标会不断变化。
3. 缩 create/h/JSX factory。
   决定 [packages/runtime/src/rue.ts](../../packages/runtime/src/rue.ts) 的 `createElement` / `createComponent` / `h` 是彻底删除，还是改成新的非-VDOM builder；无论选哪种，都不能再输出旧 mount-handle / vnode-style 形状，并且 [packages/jsx-runtime/src/index.ts](../../packages/jsx-runtime/src/index.ts)、[packages/jsx-dev-runtime/src/index.ts](../../packages/jsx-dev-runtime/src/index.ts)、[packages/rue/jsx.d.ts](../../packages/rue/jsx.d.ts) 也要一起改口径。
4. 改 renderable identity / comparator。
   同步更新 [packages/runtime-vapor/src/hook/reactive.rs](../../packages/runtime-vapor/src/hook/reactive.rs) 里 `shallow_equal_prop` / renderable identity 的判断规则，让 props/children 比较跟新的 renderable/block contract 对齐，不再默认依赖 `__rue_mount_id` / `__rue_host_node` 兼容对象。
5. 缩 package exports。
   更新 [packages/runtime/src/index.ts](../../packages/runtime/src/index.ts)、[packages/rue/src/index.ts](../../packages/rue/src/index.ts)、[packages/jsx-runtime/src/index.ts](../../packages/jsx-runtime/src/index.ts)、[packages/jsx-dev-runtime/src/index.ts](../../packages/jsx-dev-runtime/src/index.ts) 与对应类型定义，让默认公开面不再暗含 VDOM-first 使用方式。

## 工作量判断

- 规模：Large
- 预估：约 7 到 10 个工作日
- 原因：这是 Plan 12 风险最高的阶段。这里既改 public types，也改 render 行为，还会直接改变 router/compiler/custom-elements 的迁移目标。

## 依赖与风险

- 强依赖 Phase 1 先把 runtime-vapor 删成单模内核。
- 这里默认接受一次 breaking change；如果要求保留旧 `h/createElement/jsx-runtime` 名字但改内部行为，复杂度会明显提高。
- 风险最高的是 `renderAnchor` / `renderStatic` / `renderBetween` 的 owner cleanup 语义，因为它们同时影响 Teleport、Transition、RouterView、custom-elements 等仓内使用者。
- 第二个高风险点是 [packages/runtime-vapor/src/hook/reactive.rs](../../packages/runtime-vapor/src/hook/reactive.rs) 的 comparator；如果这里仍沿用旧 mount-handle identity，Phase 3 很容易出现 stale props 或重复触发更新的问题。

## 完成标准

1. [packages/runtime/src/rue.ts](../../packages/runtime/src/rue.ts) 与 [packages/runtime/src/vapor-runtime.ts](../../packages/runtime/src/vapor-runtime.ts) 不再出现 `RueMountHandle`、`compatMountHandleOwner`、`pendingCompatAnchorRenders`、`RenderOutput`。
2. `render` / `renderBetween` / `renderAnchor` / `renderStatic` 的 owner/cleanup 语义已经收敛成单一 vapor-only contract，不再依赖 compat remount sentinel。
3. [packages/runtime/src/index.ts](../../packages/runtime/src/index.ts)、[packages/rue/src/index.ts](../../packages/rue/src/index.ts)、[packages/jsx-runtime/src/index.ts](../../packages/jsx-runtime/src/index.ts)、[packages/jsx-dev-runtime/src/index.ts](../../packages/jsx-dev-runtime/src/index.ts) 与 [packages/rue/jsx.d.ts](../../packages/rue/jsx.d.ts) 默认公开面已经切到新口径。
4. [packages/runtime-vapor/src/hook/reactive.rs](../../packages/runtime-vapor/src/hook/reactive.rs) 不再把旧 mount-handle / host-node 兼容对象当成默认 renderable identity。
