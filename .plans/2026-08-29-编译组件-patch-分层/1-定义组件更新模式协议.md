## 上下文

- 编译器组件统一调用 `_$createComponent`，它映射到 `packages/runtime/src/rue.ts#createComponent`；手写 `h(Component)` 经过 `createElement`。
- 新增 portable 字段 `__rue_component_update_mode__`，值仅允许 `fine-grained` 或 `rerender`；前者由 `createComponent` 写入，后者为 `h()`/默认兼容路径。
- repeatable factory、portable key 复制和 `ComponentMountInput` 必须保留该字段；未知值应拒绝或归一到保守的 `rerender`，不得默认为 fine-grained。

## 测试计划

- 行为：编译器 helper 创建和重放的组件输入稳定携带 `fine-grained`；`h()` 创建及重放的组件输入为 `rerender`；现有外部 portable handle 未声明时保持保守重渲染。
- 失败验证测试：扩展 input protocol/interop 测试检查初次消费、repeatable replay 和缺省值；扩展 Rust 测试确认组件 JSX 仍只生成 `_$createComponent`，不生成 `h`。
- 失败验证命令：`pnpm exec vitest run packages/runtime/__tests__/runtimeVapor.js-input-protocol.spec.ts packages/runtime/__tests__/vaporEntry.interop.spec.tsx`
- 预期失败原因：portable 协议和 `ComponentMountInput` 尚无更新模式，两个创建入口不可区分。
- 通过验证命令：`pnpm exec vitest run packages/runtime/__tests__/runtimeVapor.js-input-protocol.spec.ts packages/runtime/__tests__/vaporEntry.interop.spec.tsx && cargo test -p swc_plugin_rue element_component::tests`
- 模拟策略：使用真实 runtime handle 注册表、真实 repeatable replay 和真实 SWC AST 转换，不 mock 协议解析。

## 步骤

1. 先写初次 handle、重放 handle、缺省外部 handle 和编译输出断言，运行失败验证。
2. 在共享协议中定义字段与联合类型，并加入 portable key 复制清单。
3. 让 `createComponent` 写入 `fine-grained`，让 `createElement` 的组件分支显式或缺省为 `rerender`。
4. 在 mount-input 标准化时校验并保存模式；非法值走保守兼容语义。
5. 构建 runtime-vapor 产物并运行 TypeScript、Vitest 与 Rust 聚焦测试。
