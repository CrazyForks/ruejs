## 上下文

- 当前高层字符串元素先创建 repeatable Vapor handle并附加 `Symbol.for('rue.element.head-record')`；组件更新时 runtime-vapor 读取该快照、丢弃原 handle，再重建最多两层 ElementMountInput。Transition/SSR 等其它消费者对 head-record 的用途不属于本任务删除范围。
- runtime-vapor 已原生提供 `createElement(type, props, children)` 的 MountInput 注册表；兼容 `h()` 应直接使用它并保留 repeatable、key、cleanup 与 context 元数据。
- 通用同 tag/key Element patch 只服务 `rerender` 模式；编译 native DOM 不产生 ElementMountInput，不能进入这条路径。

## 测试计划

- 行为：手写 `h()` 的同 tag/key props、事件、文本和嵌套组件可原地更新；tag/key 变化替换；Fragment/custom-element/cleanup 正常；runtime-vapor 组件更新不再依赖 stable-host 字段、head-record 反射或深度 2 限制。
- 失败验证测试：先扩展 h/component parity 与 anchor 测试覆盖三层嵌套、children 插删、key/tag 变化和 custom-element context，并增加源码架构负断言。
- 失败验证命令：`pnpm exec vitest run packages/runtime/__tests__/runtimeVapor.js-component-parity.spec.ts packages/runtime/__tests__/patchChildren.anchor.spec.ts packages/runtime/__tests__/custom-elements.spec.tsx`
- 预期失败原因：当前仅通过 head-record 快照识别原生根，且稳定 children patch 被人为限制为两级。
- 通过验证命令：`pnpm exec vitest run packages/runtime/__tests__/runtimeVapor.js-component-parity.spec.ts packages/runtime/__tests__/component.renderable.spec.tsx packages/runtime/__tests__/patchChildren.anchor.spec.ts packages/runtime/__tests__/custom-elements.spec.tsx`
- 模拟策略：使用真实 `h()`、真实 DOM adapter 与真实组件/自定义元素；不伪造 head-record。

## 步骤

1. 添加深层兼容树、key/tag 替换、事件/表单和 custom-element 正反例，确认现状的协议限制。
2. 让高层字符串/Fragment `createElement` 委托 runtime-vapor Element/Fragment MountInput，并让 repeatable factory 重放同一兼容输入。
3. 将 Element patch 改为只对 `rerender` 组件结果或完整兼容入口生效，不再依赖 stable-host 私有 props。
4. 删除 runtime-vapor 中的 `createStableNativeElementInput`、unused Vapor handle 回收桥、`RUE_STABLE_COMPONENT_HOST_KEY` 和固定 descendantDepth；仅在 Transition/SSR 等已有独立契约仍需要时保留高层 handle 的 head-record 元数据。
5. 运行聚焦测试并检查 portable handle 一次性消费、重放与 cleanup 无泄漏。
