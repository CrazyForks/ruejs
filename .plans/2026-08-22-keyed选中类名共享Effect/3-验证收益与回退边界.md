## 上下文

## 测试计划

- 行为：1k/10k keyed native-signal 选择保持正确，计算/setter 次数为常数；创建、替换、交换、删除、清空与卸载不泄漏 controller 或错误类名。
- 失败验证测试：扩展运行时集成测试，加入同 key 根替换、删除当前选中项、清空后重建、组件卸载后更新 signal、microtask 调度五类回归。
- 失败验证命令：`pnpm run prepare-unit-test-artifacts && pnpm vitest run --project unit-jsdom packages/runtime/__tests__/vaporKeyedClassEffect.spec.ts packages/runtime/__tests__/jsFrameworkBenchmark.list-performance.spec.tsx`
- 预期失败原因：若前两项只覆盖理想路径，结构替换或卸载后仍可能保留旧 DOM/旧 Map，新增回归会暴露具体缺口；若已完整则直接通过并记录无需生产修复。
- 通过验证命令：`pnpm run prepare-unit-test-artifacts && RUE_PERF_TEST=1 RUE_PERF_ROW_COUNT=1000 pnpm vitest run --project unit-jsdom packages/runtime/__tests__/jsFrameworkBenchmark.list-performance.spec.tsx --reporter=verbose`
- 模拟策略：使用真实编译产物、真实 Wasm signal/effect 和 jsdom；setter/getter 计数仅用于观察调用数量，不替代 DOM 结果断言。

4. 同时复测 create、replace、swap、remove 和 clear，确认共享 controller 的 `onCommit` 没有引入全表扫描或可复现回退。
