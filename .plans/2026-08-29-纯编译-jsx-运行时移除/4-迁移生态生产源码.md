## 上下文

- router/i18n 当前是 `.ts` 且动态创建组件、Provider 与 anchor；应优先改为 TSX 并让包构建器运行 Rue transform，真正动态的 `is/as/resolvedComponent` 交给任务 2 的编译 ABI。
- rue-design 的 `h` 多用于动态标签、图标或受控面板，必须保持 ref、slots、事件、Context 与组件 identity。

## 测试计划

- 行为：RouterView/RouterLink、i18n Provider、动态 `as`、popover/form/transfer 的渲染和更新与迁移前一致。
- 失败验证测试：为动态路由组件切换、i18n 嵌套 Provider、动态标签 ref/事件各补一条 compiler-only 测试，并断言构建产物无 `h`。
- 失败验证命令：`pnpm exec vitest run packages/router/__tests__/router.spec.tsx packages/i18n/__tests__/i18n.spec.tsx packages/rue-design/src/components/transfer/__tests__/Transfer.spec.tsx`
- 预期失败原因：生产源码仍导入已删除 `h`，`.ts` 入口不能承载 TSX。
- 通过验证命令：`pnpm exec vitest run packages/router packages/i18n packages/rue-design/src/components/transfer/__tests__/Transfer.spec.tsx && node scripts/build.js router i18n rue-design -f esm-bundler`
- 模拟策略：使用真实 router、Context 和 jsdom；仅保留已有的浏览器布局/计时模拟。

## 步骤

1. 先补动态路由、Provider 和动态标签失败验证。
2. 将静态结构改写成 TSX；对运行时类型未知的位置使用编译器支持的 `<Component is>`/动态标签语法，使输出进入专用 helper。
3. 如重命名 router/i18n 入口，更新包 entry、内部引用和声明构建输入，保证 Vite package builder 对 `.tsx` 执行 Rue transform。
4. 保持组件 props、children/slots、事件、ref、key 和 Context 语义，不复制 runtime 的规范化逻辑到业务包。
5. 构建三个包并检查发布 JS 中没有 `h(`、JSX runtime import 或残留 JSX。
