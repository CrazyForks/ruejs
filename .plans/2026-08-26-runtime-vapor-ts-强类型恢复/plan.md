# Runtime Vapor TS 强类型恢复计划

目标：把 `runtime-vapor` 的 40 个手写 JavaScript 运行时源文件恢复为严格 TypeScript，并在此基础上修复现存底层回归。

范围：覆盖 `js-reactive`、`js-runtime`、九个包根入口/桥接文件、类型声明与生成链；从 `2b5e919^` 的 Rust 源迁回中文注释；修复 Transition 卸载和应用挂载回滚；最后恢复全量回归与性能交接。

范围外：不把 wasm-bindgen 生成物或构建脚本强改为 TS；不恢复已删除的 Rust Runtime/Hook；不修改 `Teleport` 等上层组件规避底层缺陷；不修改性能预算或基线。

假设：`2b5e919` 是主体 JS 边界迁移，`5ea59c8` 是当前补丁；迁移前中文注释以 `2b5e919^`（当前为 `41552d1`）为准；当前工作树干净，旧边界计划任务 17 仍因回归阻塞。

## 设计决策

- 手写源码改为同路径 `.ts`；兼容的 `.js`、`.d.ts` 由 TypeScript 构建生成，包入口和性能测量仍消费同名 JS 产物。
- 增量迁移期间允许未迁移 JS 作为外部边界，但已迁移 TS 必须严格检查；最终关闭 `allowJs` 并禁止手写 JS、`@ts-ignore`、`@ts-nocheck` 和无说明 `any`。
- Rust 中文注释先形成逐文件保真清单，再随对应符号迁入 TS；不因实现语言变化丢弃行为说明、边界约束或示例。
- 先完成类型恢复再修缺陷；`Teleport.ts` 只作行为参考，禁止修改，根因必须落在 `runtime-vapor` 底层。

## 架构说明

- Rust/Wasm 继续只承载响应式图内核；TS façade、Hook、MountInput、Mounted 判别联合、DOM Host、组件实例和 owned mount 负责运行时外壳。
- `tsconfig` 与生成脚本分离“类型检查”和“发布产物生成”；生成 JS 不作为手写源码提交，现有模块名、Node/浏览器入口和性能预算身份保持稳定。
- 原边界计划 `plan.md` 只读；最终任务复用其批次 17 验证与交接约束，不提前执行或修改性能预算任务。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实行为，不验证模拟对象或实现细节。
