## 上下文

- `h()` 的通用字符串/组件/children 语义依赖 default createElement/portable handle；这类未编译动态能力本身不能等同于 compiled DOM helper。
- 计划目标是隔离成本：Rue SWC 输出不得引用 `h`、`jsx/jsxs/jsxDEV` 或 `@rue-js/jsx-runtime`，而不是让手写 `h(Component, dynamicProps)` 假装具备 compiled-only 能力。

## 测试计划

- 行为：compiled 消费端不含默认/Vapor runtime、自动 JSX runtime 或 `h/createElement` 实现；`h-only`/未编译 JSX 保持可用并被报告为兼容预设。
- 失败验证测试：扩展 tree-shaking 和 size-audit 测试，断言 compiled 预设的 moduleIds/源码签名及兼容预设的独立来源。
- 失败验证命令：`pnpm exec vitest run scripts/__tests__/runtime-tree-shaking.spec.ts scripts/__tests__/runtime-size-audit.spec.ts`
- 预期失败原因：现有测试没有覆盖 `h-only`、自动 JSX runtime 和 compiled 入口之间的负依赖契约。
- 通过验证命令：`pnpm exec vitest run scripts/__tests__/runtime-tree-shaking.spec.ts scripts/__tests__/runtime-size-audit.spec.ts`
- 模拟策略：使用发布入口真实 Vite bundle；不以源码字符串搜索代替 moduleIds 和最终代码双重检查。

## 步骤

1. 先新增 compiled/`h-only`/自动 JSX runtime 三类消费端断言并运行失败验证。
2. 若 compiled 已隔离，仅固化门禁；若存在静态污染，沿现有 subpath 模式拆出最小兼容入口并保持 `h()` 公共行为测试通过。
3. 更新预算：compiled 禁止 default/Vapor/JSX runtime；兼容预设禁止 Wasm、SSR 和无关 builtins，但不拿其体积冒充 compiled-core。
4. 文档明确“编译 JSX 为默认轻路径、`h()` 为显式未编译边界”，解释何时会加载通用 runtime。
5. 重跑编译器导入、tree-shaking、size audit 和 `h` 相邻生命周期测试。
