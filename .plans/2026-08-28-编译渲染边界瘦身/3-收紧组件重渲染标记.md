## 上下文

- 当前函数声明/变量组件只要 `block_has_explicit_vapor_return` 就注入 `_$vaporMarkComponentRenderReactive()`；runtime 随后创建立即执行的 watch effect，可能再次执行组件以收集依赖。
- 必须保留 early return、if/switch/条件选择等在 setup 阶段读取 signal 并决定 JSX 分支的组件级更新；返回 setup 内的动态 attr/text/list 已由局部 effect 负责。

## 测试计划

- 行为：普通 fallback 组件挂载只执行一次，setup 内标量变化不重新执行组件函数；真正的响应式控制流每次源变化只重新执行一次且保持 DOM/焦点/生命周期语义。
- 失败验证测试：编译器单测断言普通 `vapor()` 返回不注入 marker、控制流返回仍注入；新 runtime 测试记录 render 次数、节点身份、focus/selection、mounted/unmounted 次数。
- 失败验证命令：`cargo test -p swc_plugin_rue pre::`
- 预期失败原因：现有 `block_has_explicit_vapor_return` 对普通 fallback 也返回真并注入 marker。
- 通过验证命令：`pnpm exec vitest run packages/runtime/__tests__/compiledRenderBoundary.spec.tsx`
- 模拟策略：使用 jsdom、真实 SWC Wasm 产物和真实 runtime；只用计数器观察组件调用，不 mock reactive kernel 或 patcher。

## 步骤

1. 先增加 marker 正反例与 runtime render-count 测试，确认普通 fallback 出现多余执行或 marker。
2. 将“返回 Vapor”与“需要组件级重新执行”拆开；基于 setup 阶段、首个 render return 之前的响应式控制流证明决定 marker。
3. 对无法证明的控制流继续保守标记；对动态 attr/text/list 等 setup 内局部绑定不标记整个组件。
4. 构建 SWC Wasm 后运行真实编译+挂载测试，核对节点身份、焦点和生命周期。
5. 运行现有 compiled/Vapor fallback 测试，确认 Context、keyed list 和卸载清理不回归。
