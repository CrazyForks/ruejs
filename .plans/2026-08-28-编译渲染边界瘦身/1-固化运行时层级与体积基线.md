# 任务 1: 固化运行时层级与体积基线

批次：【批次 1】 依赖批次：无

状态：未开始

目的：用可复现消费端产物回答 compiled、Vapor、`h()` 和自动 JSX runtime 各自加载哪些模块及占用多少体积。

来源任务：无

预计会话范围：只扩展体积审计、单测和编译输出契约，不修改编译器 lowering 或运行时行为；输出后续任务共同使用的基线报告。

- 修改：`scripts/runtime-size-audit.js`
- 修改：`scripts/__tests__/runtime-size-audit.spec.ts`
- 修改：`scripts/runtime-size-budget.json`

- 新建证据：`temp/size/compiler-runtime-boundary-baseline.json`

## 上下文

- 当前审计已有 `compiled-core`、`vapor-core`、`full-core`，但没有 `h-only` 和 `jsx-runtime-only` 消费端预设。
- `h()` 经 `packages/runtime/src/jsx.ts` 调用默认 `createElement`；自动 JSX runtime 静态导入主入口的 `h`。Rue SWC 安全输出应完全消除这条依赖。

## 测试计划

- 行为：审计报告可区分手写兼容边界和 compiled 主路径，并证明安全编译输出不含 `h`、默认 JSX runtime 或完整 Vapor 入口。
- 失败验证测试：在 `runtime-size-audit.spec.ts` 增加 `h-only`/`jsx-runtime-only` 预设、来源字段和预算解析断言；在 `import_injection_minimal.rs` 增加安全 JSX 的导入负断言。
- 失败验证命令：`pnpm exec vitest run scripts/__tests__/runtime-size-audit.spec.ts`
- 预期失败原因：审计预设和对应报告/预算字段尚不存在。
- 通过验证命令：`pnpm exec vitest run scripts/__tests__/runtime-size-audit.spec.ts`
- 模拟策略：使用现有 Vite 消费端真实构建，不 mock resolver、tree-shaking 或压缩器。

## 步骤

1. 先补审计单测和安全编译输出断言，运行失败验证并保存预期失败。
2. 为 `h-only`、`jsx-runtime-only` 增加真实发布入口消费预设，报告 raw/min/gzip/brotli、默认/Vapor/compiled runtime 和模块清单。
3. 在预算中只约束边界事实：`compiled-core` 继续禁止默认/Vapor runtime；手写 `h`/未编译 JSX 可加载默认兼容层，但不得带 Wasm 或 SSR renderer。
4. 生成基线 JSON，记录各预设差值；不要把 `h-only` 体积误算为 compiled 应用成本。
5. 运行 Rust 导入测试和审计单测，审查报告来源字段。

## 验证

- 运行：`cargo test -p swc_plugin_rue --test import_injection_minimal`
- 运行：`pnpm exec vitest run scripts/__tests__/runtime-size-audit.spec.ts`
- 运行：`pnpm run size-runtime -- --output temp/size/compiler-runtime-boundary-baseline.json`
- 预期：命令退出码 0；报告含 `compiled-core`、`h-only`、`jsx-runtime-only`、`vapor-core`；compiled 不含默认/Vapor runtime，另外两个兼容预设不含 Wasm/SSR。
- 所需证据：失败测试输出、通过测试数量、四个预设的体积值与模块来源摘要、基线 JSON 路径。

## 完成

完成时报告新增预设名称、`compiled-core` 与 `h-only`/`jsx-runtime-only` 的 min/gzip/brotli 和来源差异，以及安全 JSX 输出中不存在的 import/call。不得借此删除或改写 `h()`。
