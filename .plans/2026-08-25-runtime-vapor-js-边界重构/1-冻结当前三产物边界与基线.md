## 上下文

- 当前浏览器完整入口使用 `pkg`，精简 Vapor 入口使用 `pkg-vapor`，Node 使用 `pkg-node`；混用两个浏览器入口时由 `vapor-bridge.js` 显式拒绝不同 Wasm 身份。
- 当前 `pkg-vapor` 的 `WasmRue` 只有 `mount`/`vapor`，而 `packages/runtime/src/vapor-runtime.ts` 仍需要更完整的 Runtime 方法；能力矩阵必须如实记录这一待迁移缺口。
- 不修改 compiler、列表 helper、`dom.ts`、性能脚本或预算。

## 验证计划

- 行为：固定三类入口的导出、Hook 语义、Wasm 身份和当前允许/拒绝的组合，并产出可供后续任务比较的基线。
- 验证测试：新增契约测试，明确区分“当前支持能力”和“迁移目标能力”；共享工具能以相同用例运行 Rust 与后续 JS 后端。
- 验证命令：`pnpm run prepare-unit-test-artifacts && pnpm exec vitest run --project unit-jsdom packages/runtime/__tests__/runtimeVapor.current-boundary-contract.spec.ts packages/runtime/__tests__/runtimeVapor.hook-contract.spec.ts && pnpm exec vitest run --project unit scripts/__tests__/runtime-vapor-artifacts.spec.ts`
- 基线命令：`pnpm run benchmark:js-framework -- --output temp/runtime-vapor-js-boundary/pre-boundary-current.json`
- 模拟策略：入口与 DOM 行为使用真实构建产物和 jsdom；只在 Hook 调度的确定性断言中使用可控调度器，不模拟 Wasm。
