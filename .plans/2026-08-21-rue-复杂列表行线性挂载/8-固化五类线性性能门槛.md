## 上下文

- 主复杂度门槛使用同进程 1k/2k 增长比；10k 证明真实规模、DOM 与生命周期正确。
- 五类要求 2k 不超过 1k 的 3 倍、初始列表正文对真实父节点最多一次写入、10k 不超过 30 秒、删除后 owner/owned mount/ref/effect 零残留；复杂列表新增全局 anchor/range entry 必须为常数而非 O(n)。

## 测试计划

- 行为：spread、ref、条件、组件和不透明调用满足增长比、单次 commit、owner 资源及 10k 清理预算；简单 benchmark 不退化。
- 失败验证测试：启用五类 `stays near-linear through 10000 rows with row-owned resources` 预算断言。
- 失败验证命令：`RUE_COMPLEX_LIST_PERF=1 pnpm exec vitest run --project unit-jsdom packages/runtime/__tests__/complexListRows.performance.spec.tsx --reporter=verbose`
- 预期失败原因：任一前置任务仍扫描全局 map、逐行写真实父节点或泄漏 owner 资源时，对应比值、计数或超时失败。
- 通过验证命令：`RUE_COMPLEX_LIST_PERF=1 pnpm exec vitest run --project unit-jsdom packages/runtime/__tests__/complexListRows.performance.spec.tsx packages/runtime/__tests__/jsFrameworkBenchmark.list-performance.spec.tsx packages/runtime/__tests__/vaporKeyedList.fast-path.spec.ts --reporter=verbose`
- 模拟策略：真实 release SWC/runtime-vapor Wasm 和 jsdom；性能断言只用墙钟增长比与真实 DOM/runtime 计数。

## 步骤

1. 将任务 1 测量转为五类明确预算并保留详细日志。
2. 构建 release SWC 与 runtime-vapor Wasm，避免陈旧产物。
3. 运行五类矩阵、简单 benchmark、owner fast path、hydration 和 lifecycle 回归。
4. 运行完整 SWC、runtime-vapor、TypeScript 检查和差异检查。
5. 审查 codegen/runtime，确认性能来自 owner 直接持有资源，不是放宽超时、跳过测试或把状态泄漏到全局 map。
