## 上下文

- wall-clock 受机器与 jsdom 波动影响，主门槛应是 owner、DOM 写入、lookup、compact 和 registry 计数；耗时增长比作为 release 构建的辅助门槛。
- 最终比较必须复用任务 1 的 fixture、构建流程、5 次 warm-up、10 次测量和中位数，不混用 debug 或陈旧 Wasm/SWC 产物。

## 测试计划

- 行为：五类主路径分别通过 mount、同 key 更新、插入、重排、删除和清空；100 轮 churn 后所有列表相关 registry 回到基线；简单列表基准不回退。
- 性能：1k/2k 的 owner/lookup/compact/DOM 操作增长近线性；2k/1k 中位耗时增长不超过 3 倍；10k 五类用例单类全流程不超过 30 秒。
- 失败验证测试：`complex list rows stay linear and release all registries`。
- 失败验证命令：`RUE_COMPLEX_LIST_PERF=1 pnpm exec vitest run --project unit-jsdom packages/runtime/__tests__/complexListRows.performance.spec.tsx -t "complex list rows stay linear and release all registries"`
- 预期失败原因：最终跨阶段计数、10k 门槛和全 registry 清零断言尚未固化。
- 通过验证命令：`pnpm --filter @rue-js/swc-plugin-rue run build && pnpm --filter @rue-js/runtime-vapor run build && RUE_COMPLEX_LIST_PERF=1 pnpm exec vitest run --project unit-jsdom packages/runtime/__tests__/complexListRows.performance.spec.tsx --reporter=verbose`
- 模拟策略：真实 release SWC、Wasm、响应式运行时和 jsdom；浏览器 E2E 只验语义，不把其 wall-clock 作为跨机器硬门槛。
