- 行为：五类形状能由真实 SWC/Wasm 编译并在 jsdom 中完成 20 行语义测试；性能模式记录 250、500、1k、2k 耗时、真实父节点写入次数、全局 anchor/range mount 增量和清理后残留，但本任务不设置增长预算，也不运行已知可能耗时数分钟的 10k 保守路径。
- 验证命令：`cargo test --manifest-path packages/swc-plugin-rue/Cargo.toml --test complex_list_rows && pnpm exec vitest run --project unit-jsdom packages/runtime/__tests__/complexListRows.performance.spec.tsx`
- 测量命令：`RUE_COMPLEX_LIST_PERF=1 pnpm exec vitest run --project unit-jsdom packages/runtime/__tests__/complexListRows.performance.spec.tsx --reporter=verbose`
- 模拟策略：使用真实 SWC 产物、真实 Rue runtime 和 jsdom；只用 spy 计数目标列表父节点的 `insertBefore`/`appendChild`，不替换 DOM 或响应式运行时。

## 步骤

1. 抽取共享数据构造和五类最小组件，确保每类只引入一个保守因素。
2. 添加 DOM 身份、更新、删除、调用顺序、ref 清理和组件 mounted/unmounted 断言。
3. 添加受 `RUE_COMPLEX_LIST_PERF=1` 控制的 250/500/1k/2k 测量、父节点写入、全局 mount 增量、清理残留计数和单类 30 秒硬超时。
4. 添加 SWC 输出形状测试，确认五类当前分别使用 `renderAnchor` 或 `renderBetween` 且未错误进入安全合并路径。
5. 运行验证与测量命令，保存控制台基线作为后续红灯对照。
