## 上下文

- Solid 的条件分支是当前 owner 的子 computation；父 owner dispose 会递归清理。Rue 当前行内条件注册到全局 renderAnchor/renderBetween map，删除外层 DOM 不等于卸载 nested mounted state。
- 本任务需要内部 owned mount API：创建时返回可直接 update/dispose 的不透明 mounted handle，由 `VaporListItemOwner` 保存；同一行更新不得再用 DOM anchor 全局查找 handle。

## 测试计划

- 行为：原生条件/fragment 行初始单次 commit；切换只更新本行；同 key 替换、删除和清空递归清除 owned mount/effect/DOM；全局 anchor/range mount 数不随行数增长。
- 失败验证测试：`complexListRows.performance.spec.tsx` 中 `native structural rows retain owned mounts without global lookup`。
- 失败验证命令：`pnpm exec vitest run --project unit-jsdom packages/runtime/__tests__/complexListRows.performance.spec.tsx -t "native structural rows retain owned mounts without global lookup"`
- 预期失败原因：当前结构行只能用全局 render map，通过 anchor/range 身份重新查找 mounted state。
- 通过验证命令：`pnpm --filter @rue-js/runtime-vapor test && pnpm exec vitest run --project unit-jsdom packages/runtime/__tests__/complexListRows.performance.spec.tsx`
- 模拟策略：真实条件切换和嵌套原生 fragment；通过 runtime mount count、DOM 与清理副作用验证，不 mock renderer。

## 步骤

1. 添加条件切换、同 key 替换、删除、清空及全局/owned mount 计数红测。
2. 在 Rust/Wasm 内部提供返回 mounted handle 的 owned mount/update/dispose 通路，不注册全局 anchor/range map。
3. JS helper 将 handle 登记到当前行 owner；owner dispose 先递归卸载 handle，再停止 ref/effects 和移除行 range。
4. SWC 让只含原生结构分支的行使用 owned slot，保持组件分支为任务 7 的负例。
5. 运行 runtime-vapor、SWC、复杂矩阵和 hydration 回归。
