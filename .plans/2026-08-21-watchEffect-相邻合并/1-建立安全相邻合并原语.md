# 任务 1: 建立安全相邻合并原语

批次：【批次 1】 无

状态：未开始

目的：提供一个只合并最大相邻编译器 `watchEffect` 段、不跨语句屏障的 AST 原语。

来源任务：无

预计会话范围：聚焦 `vapor/mod.rs` 的 watcher 解构与构造；通过纯 AST 输入输出锁定相邻、屏障、单例、非标准调用和块作用域，不接入 JSX 属性生成。

## 文件

- 修改：`packages/swc-plugin-rue/src/vapor/mod.rs`
- 测试：`packages/swc-plugin-rue/src/vapor/mod_tests.rs`

## 上下文

- `watch_effect_body` 只识别直接 `watchEffect` 调用且第一参数是箭头函数；`coalesce_list_row_binding_effects` 已用独立 `BlockStmt` 包装每个 body。新原语应复用该安全形态，但只处理连续段。

## 测试计划

- 行为：两个及以上相邻标准 effect 合并为一个；非 effect 语句切分段；单例、`obj.watchEffect`、缺少箭头参数和其它调用保持原样。
- 失败验证测试：`packages/swc-plugin-rue/src/vapor/mod_tests.rs` 中新增 `coalesce_adjacent_binding_effects_preserves_barriers_and_scopes`。
- 失败验证命令：`cargo test --manifest-path packages/swc-plugin-rue/Cargo.toml vapor::tests::coalesce_adjacent_binding_effects_preserves_barriers_and_scopes -- --exact`
- 预期失败原因：尚无相邻段合并原语，输出仍包含多个标准 `watchEffect` 调用。
- 通过验证命令：`cargo test --manifest-path packages/swc-plugin-rue/Cargo.toml vapor::tests:: -- --nocapture`
- 模拟策略：使用 SWC 真实 parser/codegen 处理 AST，不 mock AST 或 emitter。

## 步骤

1. 先写入含两个相邻段、一个屏障和非标准调用的失败测试，断言 watcher 数量、body 顺序和独立块。
2. 运行失败验证命令，确认是缺少相邻合并行为而失败。
3. 在 `vapor/mod.rs` 实现最大相邻段收集与刷新；长度为 1 的段返回原语句，长度至少为 2 时才构造合并 watcher。
4. 抽取最小的 body-block/watcher 构造帮助函数，让新原语与 `coalesce_list_row_binding_effects` 共享形态而不改变列表行语义。
5. 运行 Vapor 模块测试和 Rust 格式检查，确认原有 once/列表合并测试仍通过。

## 验证

- 运行：`cargo test --manifest-path packages/swc-plugin-rue/Cargo.toml vapor::tests:: -- --nocapture && cargo fmt --manifest-path packages/swc-plugin-rue/Cargo.toml -- --check`
- 预期：命令退出码为 0；最大相邻段各自仅有一个 watcher，屏障两侧不互相合并，原 body 顺序和块边界保留。
- 所需证据：新测试红转绿、Vapor 模块测试通过数、格式检查退出码，以及对 `coalesce_list_row_binding_effects` 差异的人工审查。

## 完成

完成时，`packages/swc-plugin-rue/src/vapor/mod.rs` 具有可由属性 emitter 安全调用的相邻合并原语；`packages/swc-plugin-rue/src/vapor/mod_tests.rs` 证明连续段、屏障、非标准形态、语句顺序与块作用域。
