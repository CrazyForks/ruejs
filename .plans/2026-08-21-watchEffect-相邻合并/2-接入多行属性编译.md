## 上下文

- `emit_attrs_for` 目前直接向调用者 `Vec<Stmt>` 追加属性语句；根元素 `jsx_to_block` 和嵌套原生元素 `build_element` 共用该入口。局部缓冲本次输出后再合并，可同时覆盖两条路径且不触及外部语句。

## 测试计划

- 行为：多行连续动态属性与 spread 产生一个 watcher；每个 body 仍依源顺序执行；静态属性、事件和 ref 会切分合并段；不同元素不共享 watcher。
- 失败验证测试：`packages/swc-plugin-rue/tests/watch_effect_coalescing.rs::multiline_adjacent_native_bindings_share_one_watch_effect_per_run`。
- 失败验证命令：`cargo test --manifest-path packages/swc-plugin-rue/Cargo.toml --test watch_effect_coalescing multiline_adjacent_native_bindings_share_one_watch_effect_per_run -- --exact`
- 预期失败原因：当前每个动态属性和 spread 都各自调用一次 `watchEffect`。
- 通过验证命令：`cargo test --manifest-path packages/swc-plugin-rue/Cargo.toml --test watch_effect_coalescing && cargo test --manifest-path packages/swc-plugin-rue/Cargo.toml attrs::tests:: && cargo test --manifest-path packages/swc-plugin-rue/Cargo.toml vapor::block::jsx::tests::`
- 模拟策略：集成测试通过真实 `apply` 转换 TSX 并检查 codegen，不 mock compiler。

## 步骤

1. 新增多行 TSX 红测，同时覆盖根元素、嵌套元素、动态 spread、屏障和不同元素边界，断言 watcher 数量与 body 顺序。
2. 运行失败验证命令，确认失败来自 watcher 数量过多。
3. 让 `emit_attrs_for` 先生成本次属性的局部语句，调用任务 1 的相邻合并原语后再按顺序追加到调用者。
4. 更新 `attrs_tests.rs` 的多动态属性断言，改为验证单 watcher、独立 body block、属性/spread 顺序和 ref/事件屏障；保留单动态属性原样输出的覆盖。
5. 在 `jsx_tests.rs` 验证根与嵌套原生元素都经过同一局部合并连线，且不跨元素合并。
6. 运行新集成测试、属性/JSX 聚焦测试、完整 SWC plugin 测试和格式检查，审查现有列表行 effect 预算仍保持。
